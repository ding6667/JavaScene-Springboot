## 交付：PPT 生成与渲染全链路改造开发文档（两份）
- 产出：`docs/ppt-render/后端改造文档.md`、`docs/ppt-render/前端改造文档.md`。用户已批准技术选型（原生 OOXML / POI 自绘）。
- **核心设计决策：DrawOp（绘制指令）作为版式层与渲染层的边界。** `LayoutRenderer` 产出 `List<DrawOp>`（rect/text/image，坐标单位 pt），由两个消费者分别执行：`OoxmlPainter` 落 POI → pptx；`PreviewSerializer` 转 JSON → 前端 DOM。前后端共用同一份几何数据，**彻底避免"前端预览与导出文件漂移"和"布局常量两边各维护一份"**。这是本次文档最重要的一条，评审时不要被简化掉。
- 坐标系定为 **960×540 pt**（PowerPoint 标准 16:9 = 13.333in×7.5in）。理由：POI `setPageSize(Dimension)` 与 `setFontSize` 单位都是 pt，`java.awt.Font.getStringBounds` 返回也是 pt → 全链路无 DPI 换算。前端 CSS 直接用 `pt`（`width: 960pt` = 1280px），同样零换算。
- fit 引擎：字体度量用**打包的思源黑体**（OFL，放 `teach/src/main/resources/ppt/fonts/`），输出字体名用 token 里的系统字体（如 Microsoft YaHei）。原因：度量必须在服务器有确定结果，输出由 PowerPoint 在用户机渲染。三档降级 = 降字号（最多 3pt）→ 按 weight 截断 70% → 拆页（最多 3 页）；高度安全系数 0.94（雅黑实际行高比理论大 5~8%）。
- IR：9 个业务 layout（COVER/AGENDA/DEFINITION/RULE/CODE/COMPARE/MISTAKE/QUIZ/SUMMARY）+ 1 兜底 BULLETS。与 Dify prompt 里已有的 9 种页面类型一一对应。代码块用 `lines: string[]` 而非多行字符串（JSON 转义易坏）。
- 表变更（`docs/sql/alter_20261030_ppt_render.sql`，文档第 8 章内）：`teach_prepare_record` +`slides_json`/`deck_source`/`render_version`；`teach_ppt` +`slide_count`/`render_version`；`teach_ppt_theme` +`token_json json`。全部可空或带默认，旧代码无感知，可单条 DROP 回滚。
- 主题令牌 4 套映射已按库内 CSS **实测值**填写（java-default 主色 #1A56A0、java-dark 底 #1E1E1E 主色 #4FC3F7、java-minimal 用 Noto Serif SC、java-uncover 是 135° 渐变 #667EEA→#764BA2）。`token_json` 为空的旧主题由 `CssTokenDeriver` 从 `css_text` 推导 → 四套存量主题无需人工录入。
- 兼容承诺：**状态机不新增枚举值**，`pptStatus`(0/1/2) 语义不变，`PptAvailabilityUtil` 不改，前端轮询一行不用改。这是评审时最关键的对前端承诺。
- 新增接口 `GET /api/teach/prepare/record/preview?recordId=` 返回 DrawOp；`renderVersion=0` 的旧记录返回 501，前端隐藏预览入口。该接口不生成文件，所以 `pptStatus=1`（文件未产出）时也能预览。
- `MarkdownToPptxUtil` 保留但降级为 fallback：`stripReasoning`/`ensureFrontmatter`/CSS 解析（`parseCssRules`/`colorOf`）都还要用，只把 `convertContent` 挪进 legacy 分支，开关 `teach.ppt.renderer=ooxml|legacy`。

## 错题本改造方案定稿（10-30 夜，仅 SQL）
- 根因：`exam_wrong_question` 只存 question_id，展示实时 join 题库 → 题库改题后错题本题面漂移；唯一键 (user_id,question_id) 把作业/刷题来源压成一条。
- 定案：错题记录自带「当时那道题」快照，唯一键改 (user_id, wrong_key)。
  - 作业来源 `P:{questionId}:{snapshotId}`（钉死 teach_homework_question），题库来源 `H:{questionId}:{fingerprint}`（内容 MD5，题改即新记录）。
  - 快照拆两包：`snapshot_view`（学生可见渲染包，含 codeFramework/requirements/hints）与 `snapshot_judge`（answer/analysis/testCases/judgeMode，永不下发），物理隔离防误泄露。
  - 列表用平铺列：short_title / question_type / score / difficulty_config_id。
  - 老数据回填当前题库内容 + `legacy=1`（当时版本已不可得）。
- 产物：`docs/sql/alter_20261030_wrong_question_snapshot.sql`（含回填与回滚），`docs/sql/table.sql` 同步。
- 已用本地 MySQL 9.3 验证：同一 ALTER 内 AFTER 链式引用可用；回填 UPDATE+JSON_OBJECT 语法通过、json 列正确内联。
- 遗留（待改代码）：`exam_homework_submit` 需加 snapshot_id；`ExamGradingService.gradeAsync` 要按提交行传 snapshotId 归档；`ExamWrongQuestionApi` 请求补 source/snapshotId/fingerprint；`listWrongQuestions` 改读快照；`markMastered` 改按 wrongKey；study 判题（`PracticeServiceImpl:146`、`StudyProgrammingApiImpl:52`）需支持按快照判题，否则重做旧编程题会用新测试用例。

## 作业断点续做（草稿保存 / 进度恢复）方案
- 产出 `docs/design/学生作业断点续做-完整方案.md` + `docs/api/学生作业续做接口-openapi.yaml`（OpenAPI 3.0.3，3 个 operation：draft / my-answers / submit）。
- 核心决策：不新建草稿表，`exam_homework_submit` 加 `status tinyint default 1`（0=草稿不批改，1=已提交），唯一键 (homework_id,user_id,question_id) 天然保证草稿转正是原地 update。
- 关键事实：全仓库读 `exam_homework_submit` 只有 `ExamHomeworkServiceImpl`（提交/我的作业）与 `ExamGradingServiceImpl#gradeAsync`(第79行) 两处；教师提交人数走 `teach.notifySubmit`，当前是空实现（TeachServiceImpl:610）。因此补 status 过滤到这几处即可闭合。
- 三个接口：`POST /api/exam/homework/draft`（不判卷、不校验截止时间、已提交题忽略并返回 ignoredQuestionIds）、`GET /api/exam/homework/my-answers`（回填草稿+已提交）、`POST /api/exam/homework/submit`（交卷：本次转正 + 其余草稿一并转正 + 全卷重算 total_score + 全量重批）。
- 顺带修既有缺陷：原 submit 的 total_score 只累加本批题目，逐题提交会把总分越改越小。
- 未落 Java 代码，等用户确认口径后实施；P0 必须先合入 DDL + gradeAsync 过滤，避免中途草稿被批改。

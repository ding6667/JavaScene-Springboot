# JavaScene 数据库分库开发文档

> 配套脚本：[`docs/sql/init_sharded_databases.sql`](init_sharded_databases.sql)（一键建库表 + 初始化必须数据）
> 适用版本：Spring Boot 3.4.5 / Spring Cloud 2024.0.3 / MySQL 9.x（utf8mb4）

## 1. 背景与目标

项目由单体迁移到微服务后，跨服务直接读对方数据库表会破坏服务边界（应走 Feign）。本次按"数据库-per-服务"做**分库**：以表名前缀划分归属，把原 `javascene` 库中的表拆分到各服务独立数据库，使每个服务只连自己的库。

- 原 `javascene` 库**原样保留**作回滚备份，不删表。
- 本轮**只建库 + 迁数据**，各服务 `application-dev.yml` 的数据源**暂未切换**（仍指向 javascene），切换见第 7 节。
- 无外键、无视图/触发器，分库无跨库约束障碍。

## 2. 分库映射

命名规则：`javascene_<服务名>`，默认字符集 `utf8mb4`、排序规则 `utf8mb4_unicode_ci`。共 **7 库 39 表**。

| 数据库 | 对应服务 | 表数 | 表清单 |
|---|---|---|---|
| `javascene_system` | system-service | 10 | sys_admin_info, sys_class, sys_permission, sys_role, sys_role_permission, sys_student_info, sys_teacher_info, sys_user, sys_user_role, standard_config |
| `javascene_study` | study-service | 5 | study_behavior, study_code_run_record, study_learning_progress, study_practice_record, study_question_status |
| `javascene_teach` | teach-service | 6 | teach_homework, teach_homework_question, teach_ppt, teach_ppt_template, teach_ppt_theme, teach_prepare_record |
| `javascene_exam` | exam-service | 6 | exam_grading_task, exam_homework_submit, exam_question, exam_question_difficulty_config, exam_question_snapshot, exam_wrong_question |
| `javascene_knowledge` | knowledge-service | 10 | knowledge_chapter, knowledge_code_snippet, knowledge_concept, knowledge_content, knowledge_difficult_point, knowledge_exercise, knowledge_keyword, knowledge_point, knowledge_upload_record, knowledge_weight_config |
| `javascene_agent_qa` | agent-qa-service | 1 | qa_record |
| `javascene_dialogue` | dialogue-service | 1 | intent_draft |

**无自有表的服务**：monitor-service、agent-code-service、agent-prepare-service、agent-question-service、agent-score-service（调用 Dify，无本地业务表），不需要独立数据库。

**非前缀表归属**（按代码 `@TableName` 核实）：
- `standard_config` → system（`StandardConfig.java`）
- `qa_record` → agent-qa（`QaRecord.java`）
- `intent_draft` → dialogue（`IntentDraft.java`）
- `user_config` → **孤儿表**（0 行、无任何代码引用），未迁移，仍留在 javascene。

## 3. 字符集与约束

- 库默认 `utf8mb4 / utf8mb4_unicode_ci`，与原 javascene 一致。
- 表级排序规则原样保留（源库混用 `utf8mb4_unicode_ci` 与 `utf8mb4_0900_ai_ci`，建表语句各自携带，不做统一改写）。
- 全部 InnoDB，**无外键**，迁移与建表无需考虑表间顺序。
- 索引、自增列定义随表结构一并迁移；一键脚本里清空了 `AUTO_INCREMENT=nnn` 的当前计数，新库从 1 起算。

## 4. 种子数据口径

一键脚本只初始化**系统运转必须的预设数据**，不含开发/测试期产生的业务数据。

**写入的种子数据：**

| 库.表 | 行数 | 说明 |
|---|---|---|
| javascene_system.sys_role | 3 | STUDENT / TEACHER / ADMIN 三个角色（鉴权基础） |
| javascene_exam.exam_question_difficulty_config | 3 | `is_system=1` 的难度预设：basic / intermediate / advanced |
| javascene_teach.teach_ppt_template | 3 | `is_system=1` 的系统 PPT 模板 |
| javascene_teach.teach_ppt_theme | 4 | 系统 PPT 主题（java-default / dark / minimal / uncover） |

**不写入的数据（运行时/测试产生）：**
- 用户与班级：sys_user、sys_student_info、sys_teacher_info、sys_class、sys_user_role（管理员由 `app.admin.init-key` 启动时自动初始化）。
- 权限：sys_permission、sys_role_permission（当前为空）。
- 教材知识库：knowledge_* 全部（上传/解析产生）。
- 学习/问答记录：study_*、qa_record、intent_draft。
- 题库与作业：exam_question、exam_question_snapshot、exam_wrong_question、exam_homework_submit、exam_grading_task、teach_homework、teach_homework_question、teach_ppt、teach_prepare_record。
- `exam_question_difficulty_config` 中 `disabled_cfg`（`is_system=0`，出题接口负向用例夹具）——属测试数据，排除。
- `standard_config`（user_id=1 的用户自建评分标准）——属用户数据，排除。

> 种子 INSERT 用 `INSERT IGNORE` + 显式列名，重复执行不产生重复行。

## 5. 一键脚本用法

脚本：`docs/sql/init_sharded_databases.sql`，**幂等**（`CREATE DATABASE/TABLE IF NOT EXISTS` + `INSERT IGNORE`），可在空环境一次性建好全部库表与种子数据，也可重复执行。

```bash
mysql -h127.0.0.1 -P3306 -uroot -p --default-character-set=utf8mb4 < docs/sql/init_sharded_databases.sql
```

本机客户端不在 PATH 时：

```bash
E:/MtSql/bin/mysql.exe --host=127.0.0.1 --port=3306 -u root --default-character-set=utf8mb4 < docs/sql/init_sharded_databases.sql
```

脚本结构：每个库一段 `CREATE DATABASE → USE → 39 表结构 → 该库种子 INSERT`。已在现有库上幂等试跑通过（无报错）。

> 注意：`docs/` 在 `.gitignore` 中，脚本与本文档默认不被 git 跟踪，需纳入版本管理时 `git add -f docs/sql/init_sharded_databases.sql`。

## 6. 本次迁移与核对结果

- 迁移方式：按分组 `mysqldump`（结构+索引+自增+数据）灌入新库，源库 javascene 不动。
- 整库备份：`temp/javascene_backup_2026-11-08.sql`（40 表，1.9MB）。
- 核对：逐表 `COUNT(*)` 比对源库与目标库，**39 表全部一致，0 处不一致**；核对脚本 `temp/verify_migration.sql` 可重跑。
- 各库表数复核：system 10 / study 5 / teach 6 / exam 6 / knowledge 10 / agent_qa 1 / dialogue 1；javascene 仍 40 表（含孤儿 user_config）。

## 7. 后续步骤：切换服务数据源（本轮未做）

分库要真正生效，需把各服务 `business-service/<svc>/src/main/resources/application-dev.yml`（及 agent-service 对应服务）的 `spring.datasource.url` 指向各自新库：

| 服务 | datasource url |
|---|---|
| system-service | jdbc:mysql://localhost:3306/javascene_system |
| study-service | jdbc:mysql://localhost:3306/javascene_study |
| teach-service | jdbc:mysql://localhost:3306/javascene_teach |
| exam-service | jdbc:mysql://localhost:3306/javascene_exam |
| knowledge-service | jdbc:mysql://localhost:3306/javascene_knowledge |
| agent-qa-service | jdbc:mysql://localhost:3306/javascene_agent_qa |
| dialogue-service | jdbc:mysql://localhost:3306/javascene_dialogue |

切换后逐个启动验证。在此之前，服务仍读写 javascene，新库为独立副本。

## 8. 注意事项

- **禁止跨库 JOIN**：分库后各服务 mapper 只能访问本库表；跨服务数据一律走 Feign（迁移已完成 Feign 化）。若仍有跨前缀 JOIN 的 SQL，切换数据源后会报错，需改为 Feign 调用。
- **数据一致性**：切换数据源前，新库是迁移时点的副本；若 javascene 之后仍有写入，切换前需重新同步增量，避免丢数据。
- **孤儿表 user_config**：确认无用时可后续清理；本轮保留在 javascene。
